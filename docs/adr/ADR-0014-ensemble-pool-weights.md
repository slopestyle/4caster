# ADR-0014 — Ансамбли в общем пуле членов и перевзвешивание §8.2

| | |
|---|---|
| **Статус** | Accepted (2026-07-27) |
| **Ревизует** | §8.2 (стартовые веса моделей) |
| **Реализует** | §10.5.1 (единый взвешенный пул), §10.5.3 (ограничители весов) |
| **Связан с** | ADR-0016 (надёжность), §8.2 E1–E2 |

## Контекст

До этой работы консенсус считался по пяти детерминированным моделям с весами
§8.2: IFS 0.30, ICON 0.28, GFS 0.20, GEM 0.14, ARPEGE 0.08 — в сумме 1.00.
Ансамблей не было, и разброс оценивался по пяти точкам. PRD прямо называет это
статистически несостоятельным (§8.2, врезка к таблице ансамблей).

При добавлении IFS ENS (51 член) и GEFS (31 член) возникают два вопроса, на
которые §8.2 ответа не даёт:

1. **Сколько весит ансамбль.** Если каждый член — полноправный участник пула, то
   82 ансамблевых члена против 5 детерминированных значений означают, что
   консенсус на 94% определяется двумя центрами (ECMWF и NCEP), а ICON, GEM и
   ARPEGE перестают на что-либо влиять. Это уничтожает саму идею
   мультимодельности (§8.1).
2. **Откуда взять вес.** Веса §8.2 уже дают в сумме единицу, свободного места
   для ансамблей в таблице нет.

## Решение

**Ансамбль весит как один источник, а не как N источников.** Вес ансамбля
делится поровну между его членами: член получает `w_j / N_j` (§10.5.1). Тогда
51 член IFS ENS суммарно весит ровно столько, сколько назначено ансамблю.

**Веса перераспределены** так, чтобы детерминированное ядро сохранило свои
пропорции, а ансамбли получили 0.40:

| Источник | Было (§8.2) | Стало |
|---|---|---|
| ECMWF IFS | 0.30 | 0.175 |
| DWD ICON | 0.28 | 0.165 |
| NOAA GFS | 0.20 | 0.115 |
| ECCC GEM | 0.14 | 0.095 |
| MF ARPEGE | 0.08 | 0.05 |
| **IFS ENS** (51 член) | — | **0.25** |
| **NOAA GEFS** (31 член) | — | **0.15** |

Проверка ограничителей §10.5.3: сумма = 1.00; ансамбли 0.40 ≤ 0.45; ни один
источник не вне [0.05, 0.40]; IFS ENS + IFS HRES = 0.425 ≤ 0.50 (они одна
система и коррелированы). Проверка выполняется **при импорте**
`consensus/models.py` и падает с `ValueError`, а не с `assert`: под `python -O`
ассерты исчезают, а это инвариант, а не отладка.

ARPEGE поднят с 0.048 до 0.05 — упирается в нижний ограничитель §10.5.3
(«ни одна доступная модель не получает вес < 0.05»), поэтому пропорции ядра
сохранены не идеально. Это сознательно: сохранение разнообразия важнее точного
масштабирования стартовых чисел, которые всё равно эвристические до Фазы 3.

**Вес ансамбля не уменьшается, если день покрыли не все члены.** Делится он
между теми, кто ответил: иначе на дальних сутках ансамбль терял бы вес просто
потому, что часть членов кончилась раньше.

## Последствия

**Плюсы**
- В пуле 87 членов вместо 5 — POP считается прямо по эмпирической CDF (§10.5.1),
  а не берётся у провайдера, и разрешена с шагом ~1%, а не ~20%.
- Появилось сырьё для компоненты E надёжности (ADR-0016).
- Мультимодельность сохранена: детерминированное ядро держит 60% веса.

**Минусы / риски**
- Числа в §8.2 больше не совпадают с кодом; источник истины по весам — реестр
  `consensus/models.py`, а таблица §8.2 остаётся стартовой гипотезой.
- Вдвое больше обращений к провайдеру: отдельный эндпоинт для ансамблей. Лимиты
  считаются по объёму, а один ансамблевый запрос тянет 82 члена — отсюда
  лимитер и предохранитель в адаптере (задача 1.2) и флаг `--no-ensembles`.
- Горизонт ансамблей — 10 суток (горизонт GEFS §8.2 E2). Дальше пул вырождается
  в пять значений, что видно в поле `n_members` каждого дня.

**Что отменит это решение:** обучение весов в Accuracy Engine (§10.8, задача
3.4). После него веса перестают быть решением архитектора и становятся
результатом измерения — эта таблица станет только начальным приближением.
