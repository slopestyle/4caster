# ADR-0016 — Надёжность на компонентах A/E/S и ERA5 seamless как источник архива

| | |
|---|---|
| **Статус** | Accepted (2026-07-27) |
| **Ревизует** | §8.4 (источник ground truth), §10.6.2 (набор компонент) |
| **Реализует** | §10.6 (A, E, S), задачу 1.7 (backfill) |
| **Связан с** | ADR-0014 (ансамбли дают компоненту E) |

## Контекст

**По надёжности.** §10.6.2 задаёт скор как произведение шести компонент
`R = 100 · A^0.28 · E^0.22 · S^0.20 · H^0.15 · G^0.10 · D^0.05`. Три из них —
H (историческая оправдываемость), G (предсказуемость режима) и D (полнота
данных) — требуют Accuracy Engine, метрик по факту и определения синоптического
режима, то есть Фазы 3. До неё скор посчитать нечем, и надёжность в Mini App
оставалась эвристикой на JS, посчитанной в слое представления.

**По архиву.** §8.4 называет источником ground truth **ERA5-Land** (9 км).
Задача 1.7 требует выгрузить архив за два сезона: без него не обучить веса
(3.4), не откалибровать скор (3.5) и не посчитать `NoiseFloor` (4.2).

При выгрузке обнаружилось, что архивный API Open-Meteo с `models=era5_land` на
диапазонах длиннее нескольких суток возвращает **`null` на весь период со
статусом 200**. Первая выгрузка записала ноль строк по всем 33 точкам и
завершилась успешно — молча. Диапазон 2024-01-01 … 2026-07-20 даёт 932 дня и
ноль непустых значений; тот же запрос с `era5_seamless` — 932 из 932.

## Решение

**1. Считать надёжность по имеющимся компонентам, перенормируя α.**

Скор считается по A, E и S, а веса α нормируются на сумму имеющихся
(0.28 + 0.22 + 0.20 = 0.70). Свёртка остаётся геометрической, поэтому провал
любой компоненты обрушивает итог — прогноз, где модели согласны, но скачут от
прогона к прогону, надёжным не считается.

Частные случаи, предусмотренные самим §10.6:
- ансамблей на день нет → `E = 0.8 · A`, и это помечается флагом
  `ensemble_is_proxy`, который виден в интерфейсе словами «ансамбли недоступны»;
- истории меньше трёх прогонов → S не считается вовсе, α перенормируются на
  две компоненты (FFI не определён: в знаменателе `n − 2`).

**2. Число наружу не отдаётся.** INV-6 и §10.6.4 требуют при
`is_calibrated = false` показывать качественную шкалу, а не балл. Домен считает
`R_raw` и хранит его для будущей калибровки, но бот и Mini App печатают слово
(«надёжно» / «осторожно» / «низкая» / «не опираться») и разбор по компонентам.

**3. Источник архива — `era5_seamless`, а не чистый ERA5-Land.** Это
ERA5-Land там, где он есть, с добором из ERA5. Мы получаем то же разрешение, где
оно доступно, и сплошное покрытие периода вместо тишины.

**4. Тихий пустой ответ считается ошибкой.** Если источник вернул N суток и ни
одного значения — это не «данных нет», а неподходящий запрос; скрипт падает с
объяснением вместо того, чтобы записать ноль строк и отчитаться об успехе.

**5. σ_clim берётся из архива.** Компонента E сравнивает разброс ансамбля с
**климатическим** разбросом: 10 мм расхождения в июле и в январе значат разное.
По выгруженному архиву посчитано стандартное отклонение суточных сумм в разрезе
«кластер × месяц» (84 ячейки, минимум 60 наблюдений на ячейку) и сложено в
`modules/reliability/data/sigma_clim.json`. Если артефакта нет, работает
запасная константа 8 мм — честнее, чем выключать E совсем.

## Последствия

**Плюсы**
- Надёжность считается в домене один раз, а бот и Mini App её только показывают
  (FR-TG-7, MB-5). Раньше логика жила в JS и дублировалась бы на два интерфейса.
- Компонента S ловит то, чего не ловит ни согласие моделей, ни разброс
  ансамблей: прогноз, который скачет от рана к рану. PRD называет её наиболее
  недооценённой — теперь она есть.
- Архив (30 756 суточных значений, полнота 100%) снимает зависимость 1.7 → 3.4,
  которая в §19.3 стоит первой в критическом пути.
- σ_clim из реальных данных сразу дала осмысленную сезонность: по кластеру
  CL-ALP-W июль 3.6 мм против января 9.0 мм.

**Минусы / риски**
- Без H и G скор систематически **завышен** на дальних сутках: §10.6.3 ожидает
  на 14-й день 12–28, а без исторической оправдываемости и предсказуемости
  режима согласный прогноз может получить больше. Это ещё одна причина не
  показывать число.
- Коэффициенты `k_S(lead)` (масштаб Flip-Flop Index по горизонту) выбраны
  провизорно: §10.6 требует калибровать их по истории, а история копится с
  апреля 2026.
- `era5_seamless` неоднороден по источнику внутри периода — для климатологии
  приемлемо, для обучения весов и метрик (3.2) однородность придётся проверить.
- Реанализ занижает пики конвекции в горах. Он не заменяет станции и IMERG,
  которые §8.4 требует для ground truth (задача 3.1) — это временная опора.
